# ProxyPress overhaul implementation brief

Work in [`zoro11031/proxypress`](https://github.com/zoro11031/proxypress). The audited GitHub baseline is [`ad32520`](https://github.com/zoro11031/proxypress/commit/ad32520cb9926ec14d591c2e3fd37e3afe56291c). Read `AGENTS.md`, inspect the working tree, and reconcile any newer code before changing it. Build and verify the overhaul end to end. Work in reviewable slices so each slice has working navigation, intact saved data, and reproducible tests.

## End goal

ProxyPress should feel like one polished desktop publishing tool. I can start a project, import and correct a deck, find any physical copy or face, inspect the sheet, tune color for my stock, and export the full job or one replacement sheet with its matching cut file. A returning user lands on a useful proof with their deck and setup intact. Order prints uses the same deck and artwork tools with an order-specific gallery and review. The experience must work on desktop, a smaller laptop window, and a phone. Advanced capabilities stay reachable through clear settings and actions.

## Visual system and responsive shell

Build a print workspace with quiet dark graphite surfaces, an off-white sheet on a distinct stage, and a restrained warm amber accent. Use one UI font family, with local font or system fallback. Keep dense UI readable, around 14px for controls and 12px for supporting labels. Use consistent spacing, control heights, dividers, icon size, focus treatment, and a small set of surface levels. Use amber for active selection and the main action. Pair warning and error colors with text. Card artwork should provide most of the visual detail. Use sticky sections only where they keep frequent actions accessible.

- **Top bar:** project picker, durable save state, and **Print at home / Order prints**. Group project creation, rename, duplication, copy decklist, shared links, and backup in a clear project menu. Put destructive actions at the end with their existing confirmation or Undo. Use one review action per mode.
- **Queue:** one **Cards** heading, physical copy count, **Add cards**, search, and **Needs attention**. For a populated project, start the rows directly below this compact header. Each row has a small thumbnail, name and optional printing or issue, one quantity control, and a visible actions button. Fit three-digit quantities. Show batch checkboxes only in multi-select, with a clear scope and an exit. Preserve select all matching copies, range selection, keyboard and touch access, and per-copy and per-face changes. First empty state offers paste and file/link import directly. Unresolved input gets a persistent **Resume import** action.
- **Stage:** keep the active sheet number, side, fit, zoom, and overlays together in one toolbar. Surface the selected card or copy near the proof with **Change art**. With no selection, use the available room for the sheet. Put **Previous / Next** and a jump field close to **Sheet X of N**. Preserve manual zoom after resizing or toggling panes. Recalculate fit only when Fit mode is active. Use the actual stage content box after toolbars, selection controls, and footer settle.
- **Setup:** use editable Paper, Layout, Sides, Cut and Calibration rows. Put Stock and printer, Driver and tray, Color tuning, Guides and registration, Advanced geometry, and Export quality in labeled disclosures. Keep one implementation for each field, with the same validation and calibration updates regardless of entry point. Use dialogs or drawers for setup at intermediate widths and a dedicated Setup view on phones.
- **Review:** one persistent action in print mode, with a real readiness state. A footer in normal grid flow can reserve its own space. If using a sticky footer, account for its measured height and the mobile safe area. Keep actionable warnings within review and link directly to the affected setting or card. Share, backup, and print instructions need their own deliberate destinations.
- **Responsive:** wide desktop shows three columns. Collapse the inspector whenever the proof would become too small, including around 1024px. At narrow widths use **Cards / Proof / Setup** with persistent review. Support phone rotation, the browser keyboard, long labels, and browser zoom. Contain intentional zoomed proof panning inside the stage. Drawers, menus, context menus, and dialogs must fit the viewport and have a clear close path. Avoid clipped focus outlines, competing sticky layers, accidental second scrollbars, and layout jumps on errors or loading.

Keep calculation code compatible with existing geometry probes. Gradually pass the job's settings into calculations that currently read `S.settings`. Store the project, job inputs, view state, and pending validation independently. A zoom or side change only redraws the proof. A paper, art, or deck change invalidates the relevant job results.

```js
// Suggested shape. Keep all lengths in mm until display or file conversion.

const scope = view.exportScope === 'current'
  ? job.sheets.filter(sheet => sheet.index === view.sheetIndex)
  : job.sheets;
const generation = ++reviewGeneration;
const review = await validatePrintJob(job, scope);
if (generation === reviewGeneration && isCurrentPrintJob(job)) {
  showPrintReview(review);

```

## Calibration and foil

**Calibration:** Stop treating an exact paper match as proof of exact duplex calibration. Model the applied profile as state rather than a hidden select and report provenance for the front and back separately. Front lookup uses printer, applicable stock or tray, dimensions, and orientation. Duplex adds feed method and flip. Retain raw legacy records and label their scope. Resolve the nested settings before an orientation transform, and apply or estimate back corrections only when the feed/flip convention supports it. Use the existing landscape-to-portrait `(X, Y) → (-Y, X)` mapping for the documented short-edge-first convention, swap scale axes, and preserve the existing rotation convention. Keep actual feed edge separate from file orientation. Route inspector fields, presets, profile loads, custom dimensions, tray/printer changes, and duplex options through the same resolution path. Offer both existing calibration sheets and an expected alignment overlay showing front and back outlines in the same physical coordinates, with measured units and readable markers. Keep the manual measurement workflow, machine-readable test-sheet keys, and scan-oriented developer checks. Validate against the existing duplex and squareness probes and physically confirm before calling a new setup measured.

**Foil:** Make the primary comparison **Adjusted artwork** beside **Estimated foil print**, in diffuse light with identical crop and scale. Use a photo of the same printed art on ProxyJak Rainbow foil as the primary evidence for darkening and saturation loss when supplied. Prefer a matching flat print photographed beside it in locked exposure and white balance. Use shadows, gray and colored midtones, and bright text boxes to choose a simple monotone tone curve. Treat values as adjustable estimates until backed by reference prints. The [ProxyJak Rainbow stock reference](https://proxyjak.com/products/uv-laser-foil-paper?variant=67798773596239) shows bare stock and can guide the optional reflection. Put **Brightness** and **Saturation** beside the comparison, with **Contrast** available for shadow detail. Add optional **Show reflection** and a user-driven tilt control as secondary tools. Render both halves from the same real print adjustments. Apply the foil preview tone model to the second half only. Keep simulation parameters out of exported pixels and geometry. Use the existing stock profiles as starting points, and add a labeled test sheet with neutral, current and alternate settings applied to the same art plus a gray ramp. Allow saving a tested printer/tray/stock setup. Use MakePlayingCards examples as background for a distinct order simulation only when it has its own printed reference.
