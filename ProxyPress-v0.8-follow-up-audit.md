# ProxyPress v0.8 follow-up audit

GitHub main was at [`8f2b699`](https://github.com/zoro11031/proxypress/commit/8f2b699753d1498ad0ac3d641e0e0d01d47ba44f). This pass compares [`11f2584`](https://github.com/zoro11031/proxypress/commit/11f2584bebae1bc58385cfc889b10696010a69bc) and the subsequent inspector change with the previous audit baseline, `ad32520`. The numbered wizard was removed from the user-facing navigation. The new code includes a one-sheet proof, current-sheet PDF export, an artwork comparison, staged imports, saved project setup, a readiness footer, and Studio support driven by the manifest. These are the foundation for the next pass.

## Visual direction for the next pass

- **Keep the compact queue, strengthen hierarchy.** Put project and mode in the top bar, the queue and its two search/filter tools in the rail, and all production actions at the bottom. Use one persistent selected-card indicator. Row labels should locate cards in the proof, while the clearly named art action edits them. Use thin separators and consistent target sizes. Keep issue text readable and avoid clipping it into the printing metadata.
- **Make the stage quiet.** Give the proof a single compact toolbar with sheet jump, front/back, fit, and overlays in logical groups. Put infrequent controls behind a labeled action. Distinguish the paper edge from the trim, bleed, and safe-area lines. Give short, simple labels to a card on each side and reserve a neutral empty state for intentionally blank sides. Avoid repeating the sheet number in several places.
- **Reduce the setup stack.** The inspector currently presents a five-field summary, then a large mounted form inside an open disclosure, then another separate cutting disclosure. Make the summary rows editable for Paper, Sides, and Cut. Keep printer profile, tray, exact color, registration, and alignment controls grouped under the related choice. Use a side drawer below a comfortable proof width and a full mobile Setup view. A single scroll owner per panel makes keyboard navigation and Focus more predictable.
- **Make review a short decision surface.** First row shows output scope and actual page count. Follow with blockers and warnings linked to their exact target. Keep the primary Download visible. Put print instructions, formats, and shared/offline files in clearly named lower-priority sections. Use the same layout in Order while labeling ZIP versus XML omissions and stock or shared-back choices directly.
- **Treat loading, failure, and saved states as part of the design.** Leave the slot and its footprint visible while downloading art. Offer a working retry at the failing source. Use a concise save state and a separate recovery action when writing fails. At present the save failure is a sentence in the top bar and Fit uses the same saving path as durable edits. Keep screen-reader state in sync with visible state, particularly the proof side and inspector button.

## Recommended order

1. Fix reachable Setup at tablet and laptop widths, copy/issue routing, and import correction destination. These affect users before a print job is ready.
2. Align cutter and PDF readiness, repair foil swatch geometry and compare real color inputs. These affect paper usage and output trust.
3. Consolidate the setup and review hierarchy, then finish import sections, art source retry and sharing choices. Validate keyboard and touch on the live app.
4. Run the regression matrix on real browser interactions. Add visible pointer clicks at 821, 1024, 1100 and 1101px, plus phone and focused proof. Test actual scrolling and focus rather than only whole-document width. Test a cube with many distinct images, throttled loads, and watch completed frame latency. Update README download filenames, current visuals, and the handoff after the verified build.
